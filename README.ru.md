# Примеры WebGPU (C++ / Dawn)

Коллекция небольших обучающих примеров для изучения **WebGPU на C++ с использованием Google Dawn**.

Эти примеры отражают мой собственный путь в графическое программирование, начиная с простого треугольника и постепенно переходя к текстурам, инстансингу, вычислительным шейдерам, постобработке и текстурам хранения (storage textures).

Главный принцип — **простота и фокус**: каждый пример представляет определенную концепцию и оставляет соответствующий код WebGPU на виду.

## Подход к обучению

Примеры расположены в рекомендуемом для изучения порядке. Более поздние примеры опираются на концепции, представленные ранее, но каждый из них собирается в отдельный исполняемый файл.

В большинстве примеров знакомый код инициализации и управления окном вынесен в локальную пару файлов `context.hpp` / `context.cpp`. Код для текущей темы остается в главном исходном файле примера вместе с шейдерами WGSL и поясняющими комментариями.

Полезный способ работы с репозиторием:

1. Соберите и запустите пример.
2. Прочитайте код и найдите новую концепцию.
3. Измените параметр, шейдер или конфигурацию ресурса.
4. Предскажите результат, а затем сравните его с тем, что произойдет на самом деле.

## Структура проекта

* **`examples/`** — исходные файлы примеров и их CMake-цели.
* **`vendors/`** — зависимости и вспомогательный код, включая GLFW, интеграцию GLFW-WebGPU и математические утилиты.
* **`utility/`** — ресурсы времени выполнения, используемые в примерах.
* **`images/`** — изображения, используемые в документации.

У каждого примера есть собственный `CMakeLists.txt`, но конфигурация начинается из корня репозитория, где настраиваются общие зависимости.

## Требования для сборки

* **Git** для клонирования репозитория.
* **CMake 3.20 или новее**.
* **C++20-совместимый компилятор**.
* Система сборки, поддерживаемая CMake, например **Ninja**, **Make** или **MSBuild**.
* Собранная и установленная копия **Google Dawn**, включая файлы пакетов CMake.
* Графические драйверы, совместимые с бэкендом Dawn, используемым в вашей системе.

GLFW и интеграция GLFW–WebGPU собираются из исходников, расположенных в `vendors/`. Вам не нужна отдельная установка GLFW для этого проекта. Для сборки GLFW могут потребоваться дополнительные пакеты разработки для вашей платформы.

### Подготовка Dawn

Следуйте официальному [руководству Dawn CMake quickstart](https://github.com/google/dawn/blob/main/docs/quickstart-cmake.md), чтобы собрать и установить Dawn.

Включите `DAWN_ENABLE_INSTALL` при конфигурации Dawn, чтобы его заголовочные файлы, библиотеки и файлы пакета CMake были установлены.

Данный репозиторий находит Dawn с помощью `find_package(Dawn REQUIRED)`. Если установка Dawn находится вне путей поиска CMake по умолчанию, укажите префикс установки через `CMAKE_PREFIX_PATH`.

## Сборка

Клонируйте репозиторий:

```sh
git clone --recurse-submodules https://github.com/con2222/webgpu-examples.git
cd webgpu-examples
```

Сконфигурируйте и соберите:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
```

Если CMake не может найти Dawn, выполните конфигурацию с указанием префикса установки:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="/path/to/dawn/install"
```

Если вы настраиваете CMake в Linux, используйте флаги для Wayland или X11:

```sh
cmake -S . -B build -DUSE_WAYLAND=ON # или -DUSE_X11=ON
```

Замените `/path/to/dawn/install` на директорию, содержащую ваш установленный пакет Dawn, а не на исходный код пакета.

### Сборка одного примера

После конфигурации проекта вы можете выбрать отдельную цель:

```sh
cmake --build build --config Release --target compute_storage_texture --parallel
```

Имена целей совпадают с названиями главных исходных файлов без `.cpp`, например: `hardcode_triangle`, `alpha_blending` и `compute_storage_texture`.

## Запуск

**Запускайте примеры, используя корень репозитория в качестве рабочей директории.** Некоторые примеры загружают ресурсы, используя относительные пути, такие как `utility/texture.jpg`.

При использовании генератора с одной конфигурацией (Ninja или Make), исполняемые файлы помещаются в директорию `build/out/`:

```sh
./build/out/compute_storage_texture
```

В Windows исполняемые файлы имеют расширение `.exe`. В Visual Studio выбранная конфигурация обычно добавляет еще одну директорию:

```powershell
.\build\out\Release\compute_storage_texture.exe
```

Если вы запускаете пример из IDE, убедитесь, что рабочая директория указывает на корень репозитория.

## Решение проблем

* **CMake не может найти Dawn:** убедитесь, что Dawn был установлен вместе с файлами пакетов CMake, затем установите `CMAKE_PREFIX_PATH` на префикс установки.
* **Изображение не загружается:** убедитесь, что требуемый ресурс существует, и что рабочая директория указывает на корень репозитория.
* **Окно не появляется:** проверьте, не выводит ли пример результаты просто в терминал.
* **Ошибка компиляции в вызовах WebGPU API:** проверьте, какая версия (ревизия) Dawn у вас установлена. Укажите эту ревизию, если будете создавать баг-репорт (issue).

При сообщении о проблеме укажите название примера, операционную систему, компилятор, ревизию Dawn и соответствующий вывод ошибки.
